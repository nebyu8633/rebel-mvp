# LifeOS — ניהול חיים ומטרות

אפליקציית ווב אישית (עברית, RTL) שמחברת מטרות שנתיות לאבני דרך, יעדים חודשיים ושבועיים, ומשימות יומיות — עם לוח שנה, שגרות חוזרות, הרגלים, תפריט ורשימת קניות, מעקב פיננסי ידני ועוזר תכנון.

> התיקייה הזו עצמאית. הקובץ `app.py` בשורש המאגר הוא פרויקט Streamlit אחר ולא נגעתי בו.

## מה יש באפליקציה

| מסך | עיקר |
|---|---|
| **היום שלי** | ברכה ותאריך (לועזי ועברי), ״הצעד החשוב ביותר״ עם הסבר איך הוא מקדם מטרה, משימות היום עם עומס מול זמן פנוי, משימות באיחור + תוכנית התאוששות, הרגלים, תזכורות, הכנה למחר, התקדמות במטרות |
| **לוח שנה** | תצוגת יום/שבוע/חודש, גרירה בין ימים ושעות (בדסקטופ), זיהוי התנגשויות, דדליינים, הבחנה בין משימות/אירועים/הרגלים, אירועים חוזרים |
| **המטרות שלי** | שלוש המטרות ההתחלתיות (אופנוע, +10 ק״ג, תיק ₪30,000) ומטרות חדשות; אבני דרך, יעדים חודשיים/שבועיים, משימות |

| **עוזר תכנון** | ״על מה להתמקד היום?״, ״פספסתי משימות…״, רשימת קניות, התקדמות, פירוק מטרה |

## הפעלה מקומית

דרישות: Node.js 20 ומעלה.

```bash
cd lifeos
npm install
npm run dev        # http://localhost:3000
```

בלי שום הגדרה האפליקציה רצה ב**מצב מקומי**: משתמש יחיד, ללא התחברות, הנתונים נשמרים ב-`localStorage` של הדפדפן ושורדים רענון — אבל לא ניקוי נתוני אתר, ולא מסתנכרנים בין מכשירים. בהגדרות ← נתונים יש ייצוא/ייבוא גיבוי JSON.

פקודות נוספות:

```bash
npm test                      # 79 בדיקות יחידה (Vitest)
npm run lint                  # בדיקת טיפוסים
npm run build && npm start    # בנייה והרצה לפרודקשן
./scripts/test-migration.sh   # מריץ את המיגרציה על PostgreSQL מקומי זמני ובודק RLS (דורש PostgreSQL 15+)
```

## משתני סביבה

מעתיקים את `.env.example` ל-`.env.local`:

| משתנה | חובה? | הסבר |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | לא | כתובת פרויקט Supabase. יחד עם המפתח הבא — מפעיל התחברות ושמירה בענן |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | לא | המפתח הציבורי (anon). כל הגישה מוגבלת ע״י RLS |
| `ANTHROPIC_API_KEY` | לא | **שרת בלבד** (בלי `NEXT_PUBLIC_`). מפעיל את תכנון ה-AI והעוזר |
| `ANTHROPIC_MODEL` | לא | ברירת מחדל `claude-opus-5-5` |

אין שימוש במפתח service-role בשום מקום, ומפתח ה-AI לא נשלח לדפדפן.

## הגדרת Supabase (שמירה בענן + התחברות)

1. יוצרים פרויקט ב-[supabase.com](https://supabase.com).
2. מריצים את המיגרציה: ב-SQL Editor מדביקים את `supabase/migrations/20261031000000_init.sql`, או עם ה-CLI: `supabase link` ואז `supabase db push`.
3. ב-Authentication ← Providers משאירים Email פעיל. ב-URL Configuration מוסיפים את כתובת האתר ואת `<site>/auth/callback` כ-Redirect URL.
4. ממלאים את שני משתני ה-`NEXT_PUBLIC_SUPABASE_*` ומפעילים מחדש.

מה מקבלים: כל דף דורש התחברות (middleware), כל טבלה עם `user_id` ומדיניות RLS שמאפשרת לכל משתמש לקרוא/לכתוב רק את השורות שלו (נבדק בסקריפט על PostgreSQL אמיתי, כולל ניסיונות גישה בין משתמשים). אין מעבר אוטומטי של נתונים ממצב מקומי — משתמשים בייצוא/ייבוא גיבוי.

**שקיפות:** סכמת ה-SQL וה-RLS נבדקו על PostgreSQL 16 מקומי, וההתאמה בין הסכמה למודל הנתונים נבדקת בבדיקות. שכבת ה-Supabase באפליקציה (התחברות, PostgREST) **לא נבדקה מול פרויקט Supabase אמיתי** בסביבת הפיתוח הזו, כי לא היו פרטי גישה.

## הגדרת AI (Anthropic)

מגדירים `ANTHROPIC_API_KEY` בשרת. השירות (`src/lib/ai/`):
- רץ בצד השרת בלבד, דרך ממשק ספק (`AIProvider`) שמאפשר להחליף ספק;
- מבקש פלט JSON מובנה (structured outputs) לפי סכמת Zod, ואז מריץ בדיקות תקינות של האפליקציה (תאריכים בטווח, משכים, תלויות לא מעגליות, מספר משימות) לפני שמשהו מוצג;
- מטפל בשגיאות (מגבלת קצב, מפתח שגוי, תקלה, סירוב) ומציג אותן — **לעולם לא ממציא תשובה מוצלחת כשהקריאה נכשלה**; המשתמש יכול לבחור במפורש לעבור למנוע הבסיסי;
- כולל הגבלת קצב פשוטה לכל משתמש (12 בקשות לדקה, בזיכרון של כל מופע שרת);
- מפעיל `fallbacks: "default"` של ה-API: אם המודל מסרב מטעמי בטיחות, ה-API מנסה מודל חלופי בעצמו.

העוזר שולח לשרת תמונת מצב מצומצמת של הנתונים של המשתמש עצמו; בענן, הנתונים נקראו דרך RLS והנתיב דורש אותה התחברות.

**בלי מפתח** הכול ממשיך לעבוד: המתכנן משתמש בתבניות שקופות (אופנוע — רק אחרי שהוזנו דגם, מחיר, חיסכון ויכולת חיסכון; משקל — רק אחרי אישור משקל התחלתי; תיק — לא ממציא שווי נוכחי), והעוזר עונה על השאלות הנפוצות בכללים מעל הנתונים. התשובות מסומנות ״מנוע בסיסי (ללא AI)״.

הקריאות ל-API נבדקו עם תעבורה מדומה (mock) בבדיקות היחידה; **לא בוצעה קריאה אמיתית ל-API** כי לא היה מפתח בסביבת הפיתוח.

## תזכורות והתראות — מה עובד ומה לא

- תזכורות בתוך האפליקציה + התראות דפדפן (אחרי מתן הרשאה), לפי אזור הזמן שהוגדר.
- כל תזכורת נשלחת פעם אחת בלבד (יומן ״נשלח״ משותף לכל הלשוניות).
- **מגבלה:** התזכורות פועלות רק כשהאפליקציה פתוחה בלשונית כלשהי. כשהכול סגור — אין תזכורות; תזכורת שהוחמצה ביותר מ-10 דקות לא מוצגת בדיעבד. התראות אמינות כשהאפליקציה סגורה דורשות שרת Web Push (VAPID + מנוי + משימה מתוזמנת) או אפליקציית מובייל — לא מומש ב-MVP. ב-iOS התראות דפדפן עובדות רק לאתר שהותקן למסך הבית.
- לא נוצרות שעות לארוחות או תזכורות שלא הגדרתם.

## החלטות מודל ונתונים

- **מקור אמת אחד למשימות.** לוח השנה, רשימת המשימות ו״היום שלי״ קוראים וכותבים את אותן רשומות.
- **משימות חוזרות** נשמרות כחוק חזרה אחד; כל מופע מחושב לפי תאריך. מופע שנגעו בו נשמר ברשומה עם מזהה דטרמיניסטי `<task>:<date>` (ייחודי גם במסד) — כך מופע לא יכול להשתכפל. נתמכים: יומי/שבועי/חודשי, מרווח, ימים בשבוע, תאריך התחלה וסיום, מספר מופעים, השהיה, ביטול מופע בודד, עריכת מופע בודד או כל הסדרה, ומדיניות פספוס (נשאר באיחור / דילוג / מעבר ליום גיבוי). השלמות עבר נשמרות גם אחרי שינוי הסדרה.
- **תאריכים ו-DST:** חישובי לוח שנה על מחרוזות `YYYY-MM-DD` (בלי חשבון מילישניות), והמרה לשעה אמיתית רק דרך אזור הזמן — נבדק על מעברי שעון ישראל וארה״ב.
- **פיננסים:** החיסכון לאופנוע והתיק הם חשבונות נפרדים. רישומים: הפקדה, משיכה, ״עדכון שווי/יתרה״. בתיק מוצג שינוי השוק בנפרד מההפקדות; ההפקדה החודשית הנדרשת מוצגת בארבעה תרחישים (0%, 2%, 5%, 8%) — כולם מסומנים כהנחות להמחשה בלבד. אין חיבור לבנק או ברוקר.
- **התאוששות ממשימות שפוספסו:** פריסה לפי חשיבות וזמן פנוי בשבוע הקרוב (לא הכול למחר), דילוג על מופעים של שגרות, החזרה ל״ללא תאריך״ של משימות בעדיפות נמוכה שלא נכנסות — והכול מוצג לאישור.
- **אין ציון כולל** לחיים; כל מדד מוצג בנפרד, ואם חסר נתון — כתוב מה חסר במקום מספר מומצא.

## מבנה

```
lifeos/
  src/app/              דפים (App Router) ו-API (/api/ai/*)
  src/components/       רכיבי UI
  src/lib/              לוגיקה: types (Zod), recurrence, tasks, finance, grocery, goals,
                        habits, recovery, reminders, planner/, ai/, store/ (local + Supabase)
  src/lib/__tests__/    בדיקות יחידה
  supabase/migrations/  סכמת SQL + RLS
  scripts/              בדיקת המיגרציה על PostgreSQL מקומי
```

סטאק: Next.js 15, React 19, TypeScript, Tailwind CSS 4, Zustand, Zod 4, Supabase (`@supabase/ssr`), Anthropic SDK, Vitest.

## מגבלות ידועות

- גרירה בלוח השנה עובדת בעכבר; במסך מגע מזיזים דרך ״תזמון מחדש״ בתפריט המשימה.
- אין סנכרון ליומן חיצוני (Google/Outlook); הלוח עובד עצמאית.
- אין מעבר נתונים אוטומטי ממצב מקומי לענן (יש ייצוא/ייבוא).
- הגבלת הקצב ל-AI היא בזיכרון של כל מופע שרת, לא גלובלית.

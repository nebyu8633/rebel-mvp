# LifeOS Mobile — מעטפת Capacitor לבדיקות במכשירים

המעטפת טוענת את אתר LifeOS **המפורסם** (אותה גרסה, אותה התחברות ואותם נתיבי שרת). היא נועדה לבדוק ביצועים במכשירים אמיתיים, ולא לפרסום בחנויות האפליקציות. לפרסום תידרש מעטפת עשירה יותר (Apple Guideline 4.2).

## דרישות
- Node 20 ומעלה.
- **Android:** Android Studio עם SDK ו-JDK 17.
- **iOS:** Mac עם Xcode ו-CocoaPods.
- כתובת שבה LifeOS מפורסם, למשל preview ב-Vercel.

## הקמה
```bash
cd lifeos-mobile
npm install
LIFEOS_URL=https://<האתר-שלך> npx cap add android   # בפעם הראשונה
LIFEOS_URL=https://<האתר-שלך> npx cap add ios        # ב-Mac
LIFEOS_URL=https://<האתר-שלך> npx cap sync           # אחרי כל שינוי כתובת
npm run android   # פותח ב-Android Studio ← Run על מכשיר מחובר
npm run ios       # פותח ב-Xcode ← בוחרים צוות חתימה ← Run
```
התיקיות `android/` ו-`ios/` נוצרות אצלך ולא נשמרות במאגר.

## בדיקת ביצועים (שלב 1)
פותחים במכשיר את `/play?bench=1`, באפליקציה או בדפדפן. בודקים שלוש פעמים, ברמה נעולה:

| בדיקה | כתובת |
|---|---|
| נמוכה | `/play?bench=1&gfx=low` |
| בינונית | `/play?bench=1&gfx=medium` |
| גבוהה | `/play?bench=1&gfx=high` |

בכל רמה: הולכים כ-30 שניות ברחוב ובכיכר, ואז לוחצים **Copy report** ושולחים לי את הדוח. הדוח כולל קצב פריימים ממוצע, זמן פריים בפריימים האיטיים (p95), draw calls, משולשים, זיכרון JS, סוג ה-GPU, רמת האיכות ו-DPR.

**קריטריונים להמשך:**
- **קצב:** לפחות 50 FPS ברמה בינונית ב-iPhone 12 או ב-Android בינוני (Pixel 6a / Galaxy A54), ולפחות 30 ברמה נמוכה במכשיר חלש.
- **טעינה:** פחות מ-4 שניות ב-4G, אחרי שמירה במטמון.
- **זיכרון:** פחות מ-400MB.
- **מכשיר חם:** לבדוק גם אחרי 5 דקות.

אם הקריטריונים לא מתקיימים — עוצרים ומחליטים לפני שמרחיבים, כולל בחינה של Unreal.
